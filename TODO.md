- [x] M-PESA remains KES-only and continues using the existing Daraja callback and verification flow.
- [x] PayPal Live remains the only card/wallet gateway, charges USD, converts donor-selected KES or INR through a server-side Frankfurter rate, and verifies the captured USD amount before completion.
- [x] Donation persistence stores original amount/currency, converted payment amount/currency, exchange rate/date, provider, transaction reference, and verified status without deleting historical records.
- [x] Paystack frontend, routes, webhooks, environment documentation, and active totals are removed while unrelated M-PESA, PayPal, church-admin, and historical database records remain intact.
- [x] Existing website branding, responsive behavior, navigation, admin access, and non-donation pages remain unchanged.
- [x] The homepage uses the permanent church coordinates latitude `1.233251` and longitude `34.936605`, timezone `Africa/Nairobi`, country Kenya, and currency KES from one central configuration.
- [x] The homepage displays the church location, a local clock and date based on `Intl.DateTimeFormat` with `Africa/Nairobi`, and Open-Meteo weather for the church coordinates; it never requests visitor GPS, refreshes weather periodically, and handles unavailable weather gracefully.
- [x] The complete live weather, clock, date, and church-location widget appears once at the bottom of the contact page, immediately before the footer and side by side with the existing live map/location block on desktop; it stacks readably on mobile and is not duplicated on the homepage or elsewhere.

# Children Sponsorship Programme Outcomes

- [x] **Responsive public navigation and programme page:** Added Children Sponsorship between Leadership and Events. Navigation follows Home, About, Services, Leadership, Children Sponsorship, Events, Contact, Admin. The programme page matches the church design and covers support for orphans, vulnerable children, families with financial need, educational, nutritional and welfare needs, objectives, profiles, relationships, and a support call-to-action.
- [x] **Responsive, consent-filtered public directories:** Seeds 30 inactive, generic sponsor placeholders with no fabricated personal identities or photographs. The public directories show only profiles approved for publication, use elegant photo placeholders, display child registration dates and sponsor status/name only when consent allows, and exclude protected location, contact, birth-date, and sensitive family information.
- [x] **Audited sponsor-to-child relationships:** Supports one sponsor for multiple children, one active sponsor per child, assignment and reassignment, active/inactive tracking, unsponsored-child identification, and retained historical assignments. Public relationships and child counts are restricted to consented, visible profiles.
- [x] **Authenticated management and statistics:** Adds the CHILDREN & SPONSORS MANAGEMENT admin section for sponsor and child records, secure photo management, assignments, relationship history, unsponsored children, and programme statistics. Sponsor placeholders require deliberate conversion and a real approved name before becoming real sponsor profiles.
- [x] **Existing PostgreSQL/backend integration:** Adds PostgreSQL schema, constraints, indexes, seed data, authenticated management APIs, soft deactivation/archive behavior, and audit history. Existing donation, Daraja, events, and church APIs were not intentionally modified.
- [x] **Secure photo upload and safeguarding:** Supports JPG/JPEG, PNG and WebP content-signature validation, a 5 MB limit, browser previews, private Cloudinary assets delivered through authenticated/signed routes, photo replacement, consent gating, and safeguarded child fields. Cloudinary environment variables must be configured in the deployed backend before photo uploads can succeed.
- [x] **Visual compatibility and regression protection:** Preserves the church branding, light/dark theme, responsive/mobile navigation, existing admin authentication and programme pages. JavaScript syntax, embedded admin script, public/admin API router behaviors, navigation order, route manifest, service-worker precache, and whitespace checks passed in the sandbox.

**Environment note:** The sponsorship schema and routes were not run against a live PostgreSQL database because no database connection is available in this workspace. The upload route correctly reports missing Cloudinary configuration; add `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` as private backend environment values before enabling photo uploads.
